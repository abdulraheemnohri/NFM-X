# Contributing to NFM-X

We welcome contributions from the community! This guide will help you get started with contributing to NFM-X.

## Code of Conduct

By participating in this project, you agree to abide by our Code of Conduct.

## How to Contribute

### Reporting Bugs
1. Check existing issues before creating a new one
2. Create a detailed issue with clear description, steps to reproduce, and environment info

### Suggesting Features
1. Check the roadmap to see if the feature is already planned
2. Create a feature request with use cases and benefits

### Contributing Code
1. Fork the repository
2. Create a feature branch (feature/your-feature-name)
3. Set up development environment
4. Make your changes
5. Run tests
6. Commit using conventional commits format
7. Push to your fork
8. Create a pull request

## Development Guidelines

### Code Style
- Follow PEP 8 guidelines
- Use type hints (Python 3.10+)
- Keep line length under 100 characters
- Add docstrings to all public functions and classes

### Testing
- Write unit tests for new functionality
- Aim for 80%+ test coverage
- Use pytest for testing

### Security
- Never commit secrets or credentials
- Use environment variables for configuration
- Report security vulnerabilities privately

## Project Structure
- backend/ - Backend application
- frontend/ - Frontend application
- docs/ - Documentation
- alembic/ - Database migrations
- tests/ - Tests

## Review Process
1. Initial review within 3-5 business days
2. Feedback and changes if needed
3. Testing by maintainers
4. Merge once approved
